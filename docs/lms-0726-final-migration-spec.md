## Phase1 function inventory — 14 proposed new functions

All functions return jsonb except the three write-lock helpers (boolean). All have search_path=''. Entry/body definitions and ownership are replay-verified. No browser or PUBLIC EXECUTE; no runtime role CREATE. Owners retain inherent execution. `R` = lms_page_reader; `W` = lms_roster_writer; `L` = lms_lineup_writer; `E` = lms_eligibility_reader; `N` = restricted trusted normal executor. R/W/L/E are NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOBYPASSRLS and not owners of public business tables. Existing service_role is trusted normal-server only; isolated origin never obtains it.

Function14 is the only addition to the earlier 13-function inventory: sharing NR/config/eligibility evaluation across Add, save and copied/manual match assignments avoids a second independent policy implementation. It performs no mutation. No new copy RPC: typed existing server assignment transaction uses12/14 within the same transaction before writing; N needs the narrowly scoped lock invocation for that normal transaction, with12 rechecking exact authority. Grant N EXECUTE on12 only for this reviewed purpose; never browser/service client supplied proof. Server handlers for the other82 transactions use the existing trusted normal service connection and fixed parameterized SQL, not a new generic mutation function. Service authority is never delegated to an isolated View-As request.

## Exact admission/locking input fields

Eligibility reads: members(id,is_active_member,dupr_id,waiver_status,membership_status,renewal_date,last_membership_sync_at,location_id,club_location); user_roles(user_id,member_id,role); teams(id,division_id,is_active,home_location_id,captain_member_id,co_captain_member_id,co_captain_2_member_id,club_pro_member_id); divisions(id,league_id,is_active,rating_type,min_dupr,max_dupr,team_dupr_max,number_of_lines,primary_team_type,secondary_number_of_lines,secondary_team_type); leagues(id,season_id,is_active,rosters_locked,only_home_community_players); seasons(id,start_date,end_date,is_active); member_season_ratings(member_id,season_id,season_dupr_rating,season_primetime_rating,dupr_doubles_rating,dupr_reliability_rating); team_members(id,team_id,member_id); locations(id,name); matches(id,home_team_id,away_team_id,league_id,division_id,status,scheduled_date); match_lineups(id,match_id,team_id,line_number,player_1_member_id,player_2_member_id); policy_bindings fields below. No email/DOB/notes inference or raw RF return. Any additional historical qualification field must already belong to the explicit match/line read groups above; absent qualifying evidence yields UNKNOWN, not an expanded arbitrary read.

Lock helpers follow the fixed ordering/context checks in four-blockers-resolution §3. Remove adds matches/match_lineups after team_members to serialize affected future-state reads; it does not need ratings/eligibility locks. No UPDATE/DELETE privileges are granted to browser/read/evaluator roles for locking. Helpers are postgres-owned, narrowly callable, fully qualified and return only boolean. Final function bodies must not make their lock list caller-selectable. READ COMMITTED fresh reads after locks; all statements/effects in one parent transaction; bounded whole-transaction retry. Never external send while locked.

## New private tables — minimum specification

Schema lms_write_private is not exposed to browser; revoke PUBLIC/anon/authenticated USAGE/CREATE and all table privileges. RLS enabled; explicit role policies for listed actions. Use uuid IDs from trusted operation identity, not member emails. Schema owner postgres.

1. policy_bindings: season_id uuid NOT NULL, league_id uuid NOT NULL, division_id uuid NOT NULL, condition_code text NOT NULL, stage text NOT NULL CHECK stage in ADMISSION/LINEUP/SEASON/MATCH, rules_version text NOT NULL, source_ref text NOT NULL, source_kind text CHECK EXISTING_COLUMN/DERIVED/UNAVAILABLE, comparison text NOT NULL, parameters jsonb NOT NULL DEFAULT '{}', config_hash text NOT NULL, status text CHECK VERIFIED/UNMAPPED/CONFLICT, reviewed_at timestamptz, reviewed_by uuid. Primary key(season_id,league_id,division_id,condition_code,stage). Scope FKs to existing hierarchy; validate hierarchy consistency. Existing min/max are referenced, not duplicated. Seed each current division/condition from final matrix; missing fact source uses UNAVAILABLE/UNMAPPED and always UNKNOWN. No row can turn unknown personal facts into PASS. E SELECT; controlled configuration publisher only writes, no browser DML. Structured parameters encode owner-approved strict RF threshold, normalization and applicability once, referenced by every evaluator; no PDF parsing. Values/versions must be reviewed seed data, not generated from untrusted prose at runtime.
2. operation_receipts: id uuid PK, actor_user_id uuid NOT NULL, request_id uuid NOT NULL, operation text NOT NULL (fixed allowed business names), resource_id uuid NOT NULL, subject_id uuid NULL, request_hash text NOT NULL, outcome jsonb NOT NULL (safe committed result only), created_at timestamptz NOT NULL DEFAULT transaction_timestamp(); UNIQUE(actor_user_id,request_id). W/L and designated normal server operations INSERT/SELECT with explicit RLS; no runtime UPDATE/DELETE. No receipt for a held/failed operation claiming success. Replays reauthorize; remove/re-add cannot turn old request into new mutation.
3. notification_outbox: id uuid PK, operation_id uuid NOT NULL REFERENCES operation_receipts(id), event_type text NOT NULL, channel text CHECK email/sms, recipient_key text NOT NULL (server-internal stable identifier), payload jsonb NOT NULL (minimum delivery template/data, protected), payload_hash text NOT NULL, state text CHECK PENDING/CLAIMED/SENT/FAILED/SKIPPED/AMBIGUOUS, first_attempt_at timestamptz NULL, claimed_at timestamptz NULL, attempts integer NOT NULL DEFAULT0 CHECK attempts>=0, provider_message_id text NULL, error_code text NULL, created_at timestamptz NOT NULL DEFAULT transaction_timestamp(); UNIQUE(operation_id,event_type,channel,recipient_key). W/L/fixed normal operation INSERT; dedicated delivery worker SELECT plus UPDATE only delivery-state columns. Never browser SELECT. Store no raw RF or admission evidence; avoid contact duplication where recipient identity suffices. Payload is sensitive delivery data, not cost telemetry. Replayed operations cannot enqueue again. Receipt/event identifiers retained while replay accepted; expired request keys must be rejected rather than treated as new sends.

No new pending-roster table, no automatic eligibility override, no new messaging scheduler/RPC is required by this specification. Delivery uses existing server execution with a bounded durable claim/poll mechanism; if a server invocation terminates, a later authorized retry drains PENDING events without regenerating a business operation. No guarantee of unattended eventual delivery without a scheduled worker is implied. AMBIGUOUS never auto-resends.

## RLS and column grants

R gets SELECT only on above field groups and reviewed scope policies; E gets only explicit eligibility columns and SELECT policy for its internal checked projection. W gets required identity/team/membership reads plus team_members INSERT/DELETE; L gets required match/lineup reads plus limited lineup INSERT/UPDATE and manager reset DELETE; no role receives broad UPDATE solely for row locks. W/L receipt/outbox INSERT permissions cannot become public RPC arbitrary INSERT because fixed functions validate all inputs. No business-table ownership or BYPASSRLS for these roles. Read entry wrappers are not mutation executors. Revoke new-function EXECUTE from PUBLIC/anon/authenticated, unrelated service/read/View-As roles in same transaction, then grant only table entries above.

Check inherited grants/role memberships and PUBLIC paths against frozen preflight before executing; unexpected source requires drift stop, not a blind global revoke. Current retained30 INSERT/UPDATE/DELETE stay RLS-manager-only; deny Player/Captain/Club Pro, and View-As executor lacks DML. No destructive live DML tests. All source/helper-executable bypasses must be negative-tested in isolated PostgreSQL. This is scoped to proven P exposures and retained dependencies, not general database hardening.

Phase1 does not include any of these Phase2 old-object changes. Clean/replay/second-replay/partial-recovery/drift procedures are normative in final-readiness-gate §5. Final owner policy is BLOCK removal until affected future/unplayed saved setup/lineup references are corrected. Remove writes no invalidity marker, performs no automatic clearing, emits no new notification and never rewrites history. Its helper locks matches, match_lineups, match_lines and line_games needed to establish current unplayed/history state in the same global order before the dependency check. Extend W SELECT to the existing explicit match/line/game identity/status/participant fields; no UPDATE/DELETE on these tables for W. Existing setup correction commits through its own authorized operation and sends its existing notice.

## Deployment incident and recovery

The first packaging attempt used git archive, which converted text files to CRLF. Byte verification failed on .gitattributes. Due to an orchestration mistake, the deployment command ran before that process result was collected, and without the expected project link it created a separate `pair-production-deploy` project/deployment `dpl_CzDZe1gmv7CL8owvrkuHHgLdPxp5`. It did not update the live LMS project. Deployment and empty project were removed; subsequent Vercel reads returned 404 for both. No production credentials were included in the source export.

Recovery used git cat-file to write exact committed bytes. The process was awaited to successful completion, all 1,198 blobs were re-hashed, and the project link plus explicit VERCEL_PROJECT_ID/VERCEL_ORG_ID pinned the correct LMS project. Only then was the approved deployment submitted. There was no SQL retry or application-code change.
